# 真实试用记录方案

目的：为项目提供可信的产品判断和量化证据。当前尚无真实试用数据。

## 第一次访谈

请一名研究员回顾最近一次信息整理任务，记录：材料来自哪里、每天处理多少、如何决定优先级、哪一步最耗时、什么错误最不能接受、最终产物如何被使用。

不要先展示工具再询问“好不好用”；先获得现有工作流和具体任务样本。

## 对照试用

选择 20–30 份获准用于测试的材料，预先由研究员标注关键事实及出处。按难度和长度分组，交叉安排人工流程与工具流程，尽可能减少先读材料造成的学习偏差。

计时应包含阅读、工具等待、修改和人工复核。不要把服务运行时间直接视为节省时间。

## 指标口径

- 关键事实覆盖率：正确覆盖的标注事实数 / 标注事实总数。
- 摘要事实准确率：经人工确认正确的输出事实数 / 输出事实总数。
- 引用支持率：经人工确认能支持摘要含义的引用数 / 引用总数。区别于程序逐字匹配率。
- 采用率：经复核采用的简报数 / 参与复核的简报数；记录修改量。
- 单任务总耗时：阅读、生成等待、修改、复核耗时之和；报告样本数及中位数。

分母为零时记录“无可用样本”，不记作 0% 或 100%。小样本只用于迭代，不外推至全团队。

## 可以积累的项目材料

- 真实访谈纪要与需求取舍。
- 版本化 PRD、工作流图、可运行演示与代码。
- 标注标准、评估样本、错误类型分析和改进前后比较。
- 实际试用记录及经确认的效率变化。
